# 03 · 软件架构

> 硬件决定上限，软件决定你离上限有多远。这一篇讲怎么组织固件，让"阅读"和"游戏"共用一套显示栈。

## 1. 任务划分

ESP32-S3 双核，一个核给"算"，一个核给"刷"：

```
Core 0                          Core 1
┌──────────────────────┐        ┌──────────────────────────┐
│ display_task (高优先) │        │ app_task (普通优先)       │
│  · 等 vsync/槽位       │        │  · 阅读：排版、断行       │
│  · diff + 生成掩码     │        │  · 游戏：模拟器核心       │
│  · SPI 传输 + 等 BUSY  │        │  · 输入扫描、UI 逻辑      │
└──────────┬───────────┘        └────────────┬─────────────┘
           │  三缓冲 handoff（指针交换，无锁）  │
           └──────────────────────────────────┘
```

- **display_task 永远不阻塞在"等新帧"上**：没新帧就什么都不做（屏幕自己保持画面）；
- **app_task 永不直接碰 SPI**，只提交位图；
- 输入、音频用独立的小任务或定时器回调。

## 2. 显示服务的接口

```c
typedef enum {
    EPD_MODE_FAST_MONO,   // 1bit，最省时间，游戏/正文
    EPD_MODE_GRAY4,       // 4 灰阶，剂量模型
    EPD_MODE_QUALITY,     // 多帧标准波形，插图/封面
} epd_mode_t;

// 提交一帧；dirty 为空表示全屏
esp_err_t epd_present(const uint8_t *fb, const epd_rect_t *dirty, epd_mode_t mode);

// 强制全刷（清鬼影）；可在阅读翻到新章节时调用
esp_err_t epd_clean(void);
```

`epd_present` 里做的事：

1. 和 `shown` 比较，逐字节 XOR 找差异 → 收缩成 `dirty` 矩形；
2. 按模式算两张掩码（1bit 直接 XOR；灰阶走剂量表）；
3. 把 `dirty` 行范围换算成控制器的 partial window（`0x11/0x44/0x45` 一类命令）；
4. 发数据、发 `0x0C`、等 BUSY；
5. 更新 `shown` 和每个像素的 `remaining/debt`。

**关键设计：`epd_present` 是异步的。** 它返回时面板可能还在刷，下一帧到来时先 `EPD_FastSync()`。这样 CPU 有 20–40 ms 去算下一帧。

## 3. 波形引擎（本项目的核心）

每个像素的软件状态：

| 字段 | 位宽 | 含义 |
|---|---|---|
| `target` | 1–2 bit | 目标色（黑白 / 4 灰） |
| `level` | 2 bit | 估计的当前亮度（灰阶模式用） |
| `remaining` | 3 bit | 还需驱动的帧数（预算余量） |
| `debt` | 4 bit 有符号 | 黑驱动 - 白驱动，用于应力记账 |

6" 1024×758 全屏 2 字节/像素 = **1.5 MB**，放 PSRAM。但**不要每帧遍历全屏**：只在 `dirty` 行范围内做逐像素运算，静态页面时这个开销接近 0。

状态机：

```
        目标变化
  HOLD ──────────> DRIVING(remaining = budget)
   ▲                    │ 每帧 -1
   │  remaining == 0    │
   └────────────────────┘
         │ 一批结束
         └──> HOLD_END（补一帧全 HOLD，让波形干净收尾）
```

维护性操作（在 display_task 的空闲时插入）：

- 每 1000 帧：软结算（只补"与当前显示同向"的债，不破坏画面）
- 每 2000–4000 帧：全刷（闪一下黑，彻底归零）
- 阅读模式：换成"每 N 页全刷一次"，由应用层显式调用 `epd_clean()`

## 4. 帧预算：为什么 SPI 时钟这么重要

一帧的墙钟时间 = **传输时间 + 面板扫描时间**，两者**串行**（控制器在刷的时候不接受新数据）：

| 面板 | 数据量（双平面） | 传输 @20MHz | 传输 @40MHz | 扫描 | 合计（40MHz） | 实际 fps |
|---|---|---|---|---|---|---|
| 1.54" 200×200 | 10 KB | 4 ms | 2 ms | 21 ms | 23 ms | 43 |
| 4.2" 400×300 | 30 KB | 12 ms | 6 ms | 30 ms | 36 ms | 28 |
| 5.83" 648×480 | 78 KB | 31 ms | 16 ms | 48 ms | 64 ms | 16 |
| 4.7" 960×540 | 130 KB | 52 ms | 26 ms | 18 ms | 44 ms | 23 |
| 6" 1024×758 | 194 KB | 78 ms | 39 ms | 76 ms | 115 ms | 9 |

**这张表是选型的量化依据**：

- 5.83" 看起来"只比 4.2" 大一点"，但双平面 78 KB 在 40 MHz 下要 16 ms，直接吃掉三分之一帧预算；
- 6" 走 SPI 是不可行的（9 fps），必须并口（16 bit/20 MHz → 194 KB 仅 97 µs）；
- **只传变化的行**能把传输时间按行数比例砍掉，这是比换总线更便宜的优化。

## 5. 阅读模式的软件设计

### 5.1 排版管线

```
EPUB/TXT ──> 文本流 ──> 断行/分页 ──> 位图页 ──> epd_present
              │            │
              │            └─ 缓存：当前页 + 下一页（预排版，翻页即用）
              └─ 字体：位图字库（12/14/16/20 px）或 stb_truetype 子集
```

- **字体**：正文用**点阵/位图字体**比矢量字体更适合墨水屏——不需要抗锯齿，1bit 渲染在 212 PPI 上已经足够锐利，而且排版快、内存小。需要多字号时预生成几套点阵。
- **断行**：中日文按字断行（禁则：行首不出现 `，。、）` 等），英文按空格 + 断词。这块自己写 300 行左右。
- **分页**：屏幕高度 / 行高，留页眉页脚。

### 5.2 翻页策略

| 策略 | 时间 | 观感 | 适用 |
|---|---|---|---|
| 直接覆盖（1bit，2–3 帧剂量） | 40–60 ms | 干净，无闪 | ✅ 默认 |
| 局部刷新（只刷变化行） | 20–40 ms | 快，但可能留残影 | 滚动、输入 |
| 整页滑动动画 | 200 ms+ | 花哨 | 不推荐（墨水屏拖影明显） |
| 全刷 | 1.3 s | 闪黑 | 每 20–50 页一次 |

**结论：翻页就是"一次 1bit 全屏重绘"，不要做动画。** 墨水屏的优雅来自"瞬间换页"，不是滑动。

### 5.3 残影管理

- 计数器：每翻一页 +1，到阈值（比如 25 页）自动插一次 `epd_clean()`，选在章节边界或用户停顿 > 3 s 时执行，避免打断阅读；
- 检测：如果用户往回翻，说明可能在找内容，**不要**在这时全刷。

## 6. 游戏模式的软件设计

```
模拟器核心（60 fps 逻辑帧）──> 帧缓冲（索引色）──> 缩放 ──> 抖动/剂量 ──> epd_present
```

- **逻辑帧率 60，显示帧率 20–30**，中间丢帧（永远显示最新帧，不排队）；
- **槽位锚定**：显示槽每 33 ms 一个，错过就跳过，不要顺延（否则延迟会累积）；
- **缩放**：整数倍最近邻（160×144 → 480×432 @3×），不要双线性（墨水屏上会糊）；
- **抖动**：固定 4×4 Bayer 矩阵，图案不随帧变化，静态元素不闪；
- **音频**：模拟器出 60 Hz 的 APU 采样，PWM/DAC 输出，和显示任务解耦。

## 7. 内存预算（6" 1024×758，1bpp 模式）

| 项 | 大小 | 位置 |
|---|---|---|
| `front` 帧（待显示） | 97 KB | PSRAM |
| `shown` 帧（当前屏上） | 97 KB | PSRAM |
| 黑/白掩码 | 2 × 97 KB | PSRAM（可复用 front 的空间优化） |
| 逐像素状态 | 1.5 MB | PSRAM |
| 页缓存（阅读） | 2 × 97 KB | PSRAM |
| 代码 + 栈 + 堆 | ~300 KB | 内部 SRAM |

8 MB PSRAM 够用，但**注意 PSRAM 的随机访问很慢**：所有逐像素循环都要按行顺序访问，不要在列方向跳。

## 9. 调试工具（先写工具，再写功能）

1. **测试图生成器**：棋盘格、灰阶条、1 px 竖线、移动方块——每种图对应一类缺陷（拖影、串扰、对齐）。
2. **应力看板**：串口打印 `debt` 直方图、全刷倒计时、平均帧时间。
3. **逻辑分析仪**：抓 SPI 命令序列，确认 LUT 装载顺序、partial window 参数正确。
4. **鬼影量化**：固定机位拍照 → Python 比对"目标图"与"实测图"的局部对比度，给残影打分，而不是靠眼睛。

## 10. 风险点

| 风险 | 表现 | 对策 |
|---|---|---|
| 波形参数不对 | 全屏发灰、对比度低 | 先用厂商 LUT 做基准，逐参数替换 |
| 电荷不平衡 | 几十分钟后出现固定鬼影 | 缩短全刷间隔，检查 budget 是否对称 |
| 传输超时 | 偶发花屏/半屏 | BUSY 用中断；SPI 加 DMA；检查 CS 时序 |
| PSRAM 带宽不足 | 帧率达不到理论值 | 局部窗口、行级 diff、双核分摊 |
| 面板个体差异 | 同型号两块屏效果不同 | VCOM 单独标定；预算存 NVS 可调 |
