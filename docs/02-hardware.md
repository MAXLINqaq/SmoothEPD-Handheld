# 02 · 硬件选型

> 选型的顺序应该是：**先定屏 → 再定驱动拓扑 → 最后定主控**。屏决定了帧率和观感，其它都能换。

## 1. 屏：唯一不可折中的部件

### 1.1 两类面板，两条技术路线

| | **带控制器的模块**（SPI） | **裸屏**（并口，无控制器） |
|---|---|---|
| 例子 | 1.54" 200×200 SSD1681；4.2" 400×300 UC8176；5.83" 648×480 UC8179 | ED047TC1 4.7" 960×540；ED060XC3 6" 1024×758；ED078KC1 7.8" 1872×1404 |
| 你写什么 | 图像平面 + LUT 寄存器 | 时序信号本身：16 bit 数据、CKV、SPH、LE、STV |
| 电压 | 模块内部升压，5V/3.3V 供电 | 自己要产生 VGH/VGL/±15V/VCOM |
| 灰阶 | 控制器查表，4 级（2bit） | 完全自由，可做 16 级 |
| 成本 | 20–120 元 | 拆机屏 60–200 元 + 电源电路 |
| 难度 | ★ | ★★★ |
| 上限 | 受控制器帧时序限制（单帧 ~20 ms） | 受面板本身限制，可到 30–57 fps |

**本项目建议：M0–M2 用带控制器的 SPI 模块练手，M3 起换裸屏并口。** 理由：先把"掩码 + 剂量 + 应力记账"这套逻辑跑通，再处理电源和时序；反过来会同时被两件事卡住。

| GDEW042T2 | 4.2" 400×300 | 140 | 300 | 15 KB | ~33 fps | SPI | ¥70–120 |

### 1.3 三块屏的取舍

- **4.7" 960×540（ED047TC1）**：目前最均衡的选择。234 PPI 足够读正文，540 行的单帧时间在 20 ms 量级，1bit 全屏 30 fps、局部窗口 50+ fps 都有希望。缺点是 4.7" 对整页 PDF 偏小。
- **6" 1024×758（ED060XC3）**：阅读体验最接近成品阅读器（212 PPI，6 寸），拆机屏便宜、货源多。代价是全屏 1bit 只有 ~13 fps，游戏必须缩到中间窗口（例如 512×384 的区域，等效 384 行，帧率翻倍）。
- **6" 300 PPI（ED060KD1）**：字最漂亮，带宽 11.6 MB/s、行数 1072，**必须**并口 + 快速主控，而且 4bpp 帧缓存要 776 KB。适合作为二代升级，不适合首版。

> **捷径**：LilyGO T5 4.7" / T5 S3 E-Paper Pro 是现成的 ED047TC1 + ESP32-S3 + 触摸 + 电池管理整板（epdiy 已支持），可以直接当 M3 的开发平台，省掉电源和 FPC 座的全部风险。自己做板放到 M5。

## 2. 驱动拓扑

### 2.1 SPI 模块（路线 A/B）

```
ESP32-S3 ──SPI(20–80MHz)──> 控制器 ──> 面板
          ├─ CS / DC / RST
          └─ BUSY（中断唤醒，别轮询）
```

要点：
- BUSY 接 **EXTI**，用中断/任务通知等待，别 busy-wait（一帧 20 ms，够睡一觉）；
- 升压（booster）**开一次就别关**，关一次再开要 ~90 ms；
- 只用**易失**的 LUT 命令（SSD1681 是 `0x32`），绝不碰 OTP 烧写命令（`0x30`）——那是不可逆的。

### 2.2 裸屏并口（路线 C）

```
ESP32-S3 ──LCD_CAM i80──> 16bit 数据总线 ──> 面板源极驱动
          ├─ CKV / SPH / LE / STV（栅极时序，GPIO 或 RMT）
          └─ TPS65185（I2C）──> VGH +22V / VGL −20V / ±15V / VCOM
```

- 时序本质是"每行：发 16 bit 像素 → SPH 脉冲 → 行末 LE → CKV 推一行"，ESP32-S3 的 LCD_CAM 在 i80 模式可以 DMA 连续输出，一帧 97 KB 用 16 bit/20 MHz ≈ 97 µs 发完，瓶颈在面板行周期不在总线；
- **TPS65185** 是专用 EPD PMIC（I2C 控制，带 power-good 和温度补偿接口），比用 MT3608 + 电荷泵自己搭稳得多，VCOM 还要按屏标定；
- 帧缓存：6" 1bpp = 97 KB（放 PSRAM 可以，放内部 SRAM 也行），4bpp = 388 KB（必须 PSRAM）。

## 3. 主控

| 候选 | 优势 | 劣势 | 结论 |
|---|---|---|---|
| **ESP32-S3**（240 MHz 双核，8 MB PSRAM） | LCD_CAM 并口、USB、成熟 IDF、InkBoy/PaperBoy/epdiy 全都用它 | PSRAM 带宽有限；无 MMU | ✅ **首选** |
| CH32H417（RISC-V 双核 + LTDC） | SmoothEPD 的原平台，便宜，国产工具链 | 生态薄、资料以中文社区为主 | 备选，学习 LTDC 时序的好平台 |
| STM32H7（LTDC + SDRAM） | 时序控制最强，DMA 双缓冲 | 贵（¥80+）、功耗高 | 不必要 |
| Linux SoC（T113-S3 / V3s） | 能直接跑 KOReader | EPD 实时时序难保证，1bit 快刷要从用户态打寄存器 | 未来做"纯阅读器"时再评估 |

**决定：ESP32-S3。** 不是因为最强，而是因为**上游三个成功项目都验证过它**，出问题时有对照物。

## 4. 电源

- **电池**：1500–2500 mAh 锂聚合物，3.7 V；
- **充电**：TP4056（便宜）/ ETA6098（带路径管理，边充边用）；
- **电量计**：MAX17048（I2C，比 ADC 分压准得多）；
- **系统轨**：3.3 V（ESP32 + 屏逻辑）、5 V（部分屏模块）、EPD 高压（模块内部或 TPS65185）；
- **功耗预期**：阅读（静态）≈ 5–15 mW；翻页瞬间 200–400 mW；游戏 30 fps ≈ 250–400 mW。所以 2000 mAh 电池：游戏 5–7 小时，阅读 2–4 周（按每天 1 小时、其余深睡）。

## 5. 输入与音频

- **按键**：十字键（或 5 向锅仔片）+ A/B + Start/Select + 左右肩键（阅读时当翻页）+ 电源键。用 **ADC 按键矩阵**省 IO，或直接 GPIO + 二极管。
- **摇杆**：可选，阅读器用不上，GB 也不需要，建议**不做**，省空间。
- **触摸**：GT911（I2C）可选。墨水屏的触控反馈天然延迟，只在菜单里有意义——首版可以省。
- **音频**：ES8311（I2S + 功放，InkBoy 方案）音质好；极简方案用 PWM/PDM 直推蜂鸣器，GB 的方波音色反而更"对味"。首版建议 **PWM 蜂鸣 + 预留 I2S 焊盘**。

### 方案 B · 掌机（¥250–350）

目标：212–234 PPI 阅读 + 窗口化游戏。**这是本项目的"成品"目标。**

## 8. 采购清单与坑

- **屏一定要买带 FPC 转接板或自带排线的**；裸屏的 34/40 pin 座（THD0515-34CL、FH12-40S）0.5 mm 间距，手工焊基本不可能，必须买转接板或直接买带座的驱动板。
- **拆机屏的 VCOM 是每块不同的**，必须能调；TPSC 板一般有 I2C 调 VCOM 的接口。
- **1.54" 模块有很多版本**（SSD1681 / SSD1608 / UC8151），买之前确认控制器型号，LUT 寄存器地址不一样。
- **别买"三色/四色"屏**（黑/白/红），它们的粒子体系不同，快刷表现很差。
- **柔性屏（Plastic Logic）不要碰**。
