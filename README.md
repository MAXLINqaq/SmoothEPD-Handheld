# SmoothEPD-Handheld

> 一台用高刷电子墨水屏做的掌上 2D 游戏机：跑自己写的游戏，20–30 fps，一充用一周。

**状态：硬件已下单，等待到货** · **👉 从 [11 开工指南](docs/11-getting-started.md) 开始** · 目标读者：有一定基础、想从零做一台墨水屏掌机的电子/嵌入式爱好者

> ⚠️ **2026-10-29 方向调整**：放弃阅读器功能，专注高刷 2D 游戏（见 [ADR-005](docs/00-decisions.md)）。下文第 1、3 节里关于"阅读"的内容仅作背景保留。

## 1. 这个项目要做什么

市面上有两种设备：读得舒服的墨水屏阅读器（但翻页慢、不能玩游戏），和刷新够快的 LCD 掌机（但背光刺眼、续航短）。本项目想验证第三种可能：

- **阅读模式**：高分辨率、灰度抗锯齿、翻页无闪、待机数周
- **游戏模式**：把同一块屏切到 1bit 高速波形，用 20–50 fps 跑复古游戏
- **一套硬件、两种波形**——屏幕不换，换的是驱动方式

这不是"把墨水屏超频"的炫技，而是一个需要认真处理**电荷平衡、鬼影、寿命**的工程问题。仓库里的文档会把这些约束写清楚，而不是只放一个 demo。

## 2. 为什么可能（三句话）

1. **"快"是波形属性，不是屏幕属性。** 墨水屏的刷新慢，慢在控制器执行的那张波形表（LUT）上有几十个电压帧：标准局部刷新约 360 ms，全刷约 1.3 s。
2. **把波形压到一帧，并只驱动"变了的像素"。** 控制器有两个图像平面，每个像素的两位决定它在这次扫描里"保持 / 往黑推 / 往白推"。不变的像素不受扰动，一次扫描就只剩一帧的时间。
3. **帧时间 ≈ 行数 × 行周期。** 200 行的 1.54" 屏单帧实测 21.26 ms（≈47 fps）；758 行的 6" 屏若行周期相近就是 ~76 ms（≈13 fps）。**行数决定帧率上限，像素数决定带宽需求**——这就是本项目的选型主线。

## 3. 目标指标

| 指标 | 阅读模式 | 游戏模式 | 备注 |
|---|---|---|---|
| 屏幕 | 4.7"（960×540，234 PPI） | 同左 | 6" 备选；屏幕是唯一不可折中的部件 |
| 灰阶 | 16 级（文字可用 1bit + 抗锯齿字体） | 4 级或 2 级抖动 | 灰度靠"剂量计数"实现 |
| 刷新 | 翻页 < 150 ms，无全屏黑闪 | 20–50 fps，局部窗口可更高 | 受行数硬约束 |
| 残影 | 每 N 页自动全刷一次 | HOLD 收尾 + 周期性清洁 | 直流应力必须记账 |
| 续航 | 每天 1 小时 ≈ 2–4 周 | 连续 5–8 小时 | 1500 mAh 量级 |
| 形态 | 单手可持，实体翻页键 | 十字键 + AB + 肩键 | 一套按键兼顾两种模式 |
| 成本 | 单台 ≤ ¥600（不含 3D 打印与工具） | | 见 [BOM](docs/05-bom.md) |

```
│                        应用层                                 │

└───────────────┬──────────────────────────┬───────────────────┘
                │ 页面位图 (1/4/16bpp)      │ 帧位图 (1/2bpp)
        ┌───────▼──────────────────────────▼───────┐
        │        显示服务 display_service          │
        │  · 模式切换（TEXT_FAST / GAME_DITHER …）  │
        │  · 脏矩形 / 行范围裁剪                    │
        │  · 三缓冲交接（渲染不阻塞扫描）           │
        └───────┬──────────────────────────────────┘
                │ 目标帧 + 上次显示帧
        ┌───────▼──────────────────────────────────┐
        │        波形引擎 waveform engine           │
        │  · 逐像素剂量计数 / 剩余脉冲预算          │
        │  · 黑掩码 + 白掩码（两平面）              │
        │  · 直流应力记账、HOLD 收尾、定期全刷      │
        └───────┬──────────────────────────────────┘
                │ 命令 + 2 个平面
        ┌───────▼──────────────────────────────────┐
        │   面板驱动 panel driver（SPI / 并口）     │
        │  · LUT 装载、升压使能、BUSY 等待          │
        └───────┬──────────────────────────────────┘
                │
          ╔═════▼═════╗
          ║  EPD 面板  ║
          ╚═══════════╝
```

## 5. 三条硬件路线（难度递增）

| 路线 | 屏 | 主控 | 帧率预期 | 难度 | 适合 |
|---|---|---|---|---|---|
| **A 验证机** | 4.2" 400×300 UC8176（SPI） | ESP32-S3 | ~30 fps | ★☆☆ | 跑通波形引擎，成本 < ¥200 |
| **B 主力** | **4.7" 960×540 ED047TC1（并口）** | ESP32-S3 + TPS65185 | **30–57 fps** | ★★☆ | 阅读 + 游戏都要 |
| **C 备选** | 6" 1024×758（裸屏，并口） | ESP32-S3 + TPS65185 | ~13 fps 全屏 | ★★★ | GBA 4× 整数缩放最优 |

选型依据、面板参数对照和决策矩阵见 [docs/02-hardware.md](docs/02-hardware.md)。

## 6. 软件栈

- **底座**：ESP-IDF 5.x（FreeRTOS 双核；显示任务钉在一个核上，模拟器/排版占用另一个核）
- **显示**：自研 waveform engine（本仓库核心）+ 面板驱动薄层
- **阅读**：TXT 先做，EPUB 次之；自研断行/排版（不引 FreeType 全量，用位图字体或 stb_truetype 子集）
- **游戏**：GB 用 Peanut-GB，NES 用 nesc 类核心；音频走 ES8311 或 PWM 蜂鸣
- **存储**：microSD（FAT32），书籍与 ROM 分离目录

本项目的驱动思路来自以下开源工作，**代码从零实现**，但概念与参数经验大量借鉴：

> ⚠️ **安全提示**：自定义波形与超高刷新率可能造成**永久性图像残留甚至面板损坏**。上游项目对此均有明确警告。本项目的所有实验以"可替换的廉价面板"为前提，不要拿唯一一块好屏做实验。
